# quick tier モデル評価（2026-10・v2.2.0）

## 目的

quick tier（8GB RAM機向けの既定チャットモデル）の品質改善候補として、手持ちの2モデルを
同一シナリオで比較し、既定を変更するかを判定する。

## 方法

- ハーネス: `spikes/phase0/latency-cmp/scenario-test.ps1` + `scenarios.json`（基礎18問）
- 同一KB（オフィス規程系・36チャンク）/ 同一エンジン（llama.cpp b10936 CPU）/ ctx 4096
- リランカー・埋め込みは共通（bge-m3 / bge-reranker-v2-m3 Q8）
- 測定: 合格数・応答時間（SSE done の ms）・llama-server 全プロセスのワーキングセット合計

## 結果

| 指標 | Qwen3-1.7B-IQ4_XS（現行quick） | Qwen3-4B-Instruct-2507-IQ4_XS |
|---|---|---|
| スコア | **16/18** | 16/18 |
| 不合格 | s07（出張申請期限）, s12（駐車場） | s11（会議室 2/3の事実）, s12（駐車場） |
| 応答時間の範囲 | 3.4〜15.3秒 | 3.5〜21.5秒（概ね1.8倍） |
| llama-server RAM合計 | 約2.8GB | 約4.2GB |

## 判定: **1.7Bを維持（既定変更なし）**

判定ルール「遅延≤2倍・8GB機のRAM内・品質が有意に改善」のうち、品質改善が成立しなかった:

- スコアは同点。不合格の内訳が入れ替わっただけ（1.7B: s07 / 4B: s11）
- s12（駐車場）はKBに料金記載が無いための拒否で、モデル非依存の既知挙動
- 4Bは遅延1.8倍・RAM +1.4GB。8GB機ではembed/rankと合算して余裕が削れる

## 備考

- 再評価の機会: 日本語に強い小型モデル（新しいGGUFリリース）が出た場合、本手順で再比較する

- s07（1.7Bで不合格）は「出張申請はいつまでに。長期出張の場合は？」の2段質問 — quick tierの
  網羅性限界。standard tierでは合格（本評価と同条件の v220 シリーズで確認済み）
