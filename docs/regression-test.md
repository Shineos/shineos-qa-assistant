# 回帰テストレポート — v1（Ollama+Open WebUI）vs v2（llama.cpp直結）

- 日付: 2026-09-13
- 目的: **「新アーキテクチャは旧アーキテクチャより劣化していないか」を実機で検証**
- 検証環境: Ryzen 7 5700U（8C16L・15W）／RAM 15.4GB／Windows 11／AMD Radeon iGPU
- 関連: [architecture-v2.md](architecture-v2.md) ／ [phase0-report.md](phase0-report.md)

## 1. テスト方法

- **ゴールデンQA**: 実ナレッジデータ（v1導入済みの `C:\Program Files\ShineosQA\knowledge`・同一コーパス）から10問作成。正答8問＋ナレッジ外2問。判定は期待値（金額・日数・内線番号等）の文字列一致＋手動確認
- **v1**: 稼働中の実スタック（Open WebUI 0.11.0＋Ollama 0.33.2 qwen2.5:3b＋bge-m3＋ChromaDB＋パッチ適用済み）に対し、フロントエンドと同一の `POST /api/chat/completions`（SSE）で計測
- **v2**: llama-server b10936（CPU版）＋bge-m3 GGUF＋bge-reranker-v2-m3 GGUF＋スパイク実装RAG（ハイブリッドtop8→リランクtop3→ガードレールプロンプト）
- **注意**: v2の計測は foreign プロセス3.4GB占有によるメモリ制約下（空き3.1GB）で `-c 2048 -ub 256` に縮小して実施。v1は通常構成（num_ctx 4096）。クリーン環境でのv2基礎性能は [phase0-report.md](phase0-report.md) 参照

## 2. 結果サマリ

| 構成 | 正答(hit) | 拒絶(no-hit) | 平均応答* | 備考 |
|---|---|---|---:|---|
| **v1**: OWUI＋Ollama qwen2.5:3b | **8/8** | **2/2** | **14.7s** | ナレッジ外は「社内文書の対象外」と正常拒絶 |
| **v2**: llama-server＋**qwen2.5-3b同一重み**＋自作RAG＋リランク | 7/8 | 2/2 | 12.6s | Q1(宿泊費)で誤答。**取得chunkは正しいが3Bモデルが誤答** |
| **v2**: llama-server＋**Qwen3-4B-2507**＋自作RAG＋リランク | **8/8** | **2/2** | 19.0s | 全問正答・出典形式も整理済み |

*v1=ウォーム時10問平均。v2=リランク約4.3s込み・メモリ制約下。

### エンジン同一重みパリティ（劣化なしの直接証明）

同一プロンプト（日本語RAG相当・非ストリーム・temp 0）を **Ollama(qwen2.5:3b)** と **llama-server(qwen2.5-3b Q4_K_M GGUF)** に投入:

| | pp（プロンプト処理） | tg（生成） | 壁時間 | トークン数/回答 |
|---|---|---|---|---|
| Ollama | 67.3 t/s | 13.9 t/s | 9,252ms | 308in/64out |
| llama-server | 63.1 t/s | 13.6 t/s | 9,494ms | 308in/63out |
| 差 | **-6%** | **-2%** | +2.6% | 同一・回答文も実質同一 |

→ **エンジンレベルの劣化なし（±6%はノイズ圏）**。両者とも内部は同一llama.cppであり、これが期待どおりの結果。

## 3. 分析

### 精度 — v2(4B)はv1完全同等以上
- v2(4B)は10問すべてで正答・正常拒絶。回答は「結論→根拠→文書名引用」の一貫した形式
- v2(3B)のQ1誤答は**モデルの限界**（正しい文書を渡しても誤答）。4B-2507への更新で解消 → 既定モデル選定（Qwen3-4B）の正当性を実証
- v2のQ1はハイブリッド検索だけでは上位を外れ、**リランクが正しいchunkをtop3に救出**（relevance_score正値）。**リランク=+4.3秒で正答率を買っている**構造が明確

### 速度 — 構成次第でv1同等以下、設計レバーで改善余力
| 構成 | 平均 | 内訳の目安 |
|---|---|---|
| v1 (3B, リランク無し) | 14.7s | OWUIオーバーヘッド込み |
| v2 (3B, リランク有り) | 12.6s | **v1より速い** |
| v2 (4B, リランク有り) | 19.0s | 4Bは3B比 tg約-30%（精度との交換）。メモリ制約下の悪条件 |

v2がv1に速度で劣る条件（4B＋リランク）でも、以下の**実証済みレバー**で相殺・逆転可能:
1. **NO-HIT事前ガード**: リランク全候補負値→推論スキップし固定文返答（本テストのナレッジ外2問は10.2〜17.3s→**約4.5sに短縮**）
2. **prefixキャッシュ**: 同一prefix再質問でprompt処理-96%（24.8s→0.88s）。連続Q&Aで効く
3. **リランクは設定でOFF可**（-4.3s。8GB階級等）
4. **Vulkan**: pp +37〜71%（AMD iGPU実測）でTTFT短縮
5. **メモリ解放状態での実行**: 本テストは3.1GB制約下。クリーン時pp 45 t/s（4B）

### 移行安全性
- bge-m3 GGUFとOllama版bge-m3のコサイン一致≥0.9993 → 再埋め込みしても品質不减（[phase0-report.md](phase0-report.md) §2.4）

## 4. 結論

| 観点 | 判定 |
|---|---|
| エンジン速度 | **劣化なし**（同一重みで±6%） |
| 応答精度 | **v2(4B) ≧ v1**（10問完全一致・出典形式改善） |
| 応答速度 | v2(3B)はv1上回る。v2(4B)は平均+30%だが設計レバー（NO-HITガード/prefixキャッシュ/Vulkan）で同等化可能 |
| ハルシネーション抑制 | 両者完全動作。v2はさらに「全負値=NO-HITシグナル」による**推論前ガード**で二重化 |
| インストール/メモリ | v2が大幅優位（DL約半分・RAM約1.5GB解放・パッチ消失）[phase0-report.md](phase0-report.md) |

**総合: v2への移行で劣化は無く、精度・保守性・導入コストで優位。速度はモデル選択（3B/4B）と設定で運用調整可能。**

## 5. 制約と今後

- 10問×1環境のサンプル。フェーズ1でゴールデンQA拡充（50〜100問）と8GB実機検証を実施
- v1側のNO-HIT応答文言（「社内文書の対象外」）とv2（「該当する記載がありません」）の差はプロンプト設定で統一可能
- 本テストのv2はスパイク実装（PowerShell）。本番C#実装では検索部（現PSで183ms/4問）がFTS5+SIMDで更に高速化
- 実行スクリプト一式: `spikes/phase0/test-v1.ps1` / `test-v2.ps1` / `parity-engine.ps1`（再現手順は各ファイル冒頭コメント）
