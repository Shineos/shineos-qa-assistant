# 技術資料（テクニカルノート）

本ドキュメントは「社内知恵袋」の技術的な詳細をまとめた参照資料です。製品の紹介は [README.md](../README.md) / English: [README-EN.md](../README-EN.md)、バージョンごとの変更は [CHANGELOG.md](../CHANGELOG.md) を参照してください。

## メモリ使用量と他アプリへの影響

AI モデルの実行にはメモリを使用しますが、**他のアプリへの影響を抑えるための自動調整**が入っています:

| 項目 | 内容 |
|------|------|
| GPU / CPU の自動判定 | インストール時に GPU を検出（`gpu_mode.txt` に記録）。**NVIDIA GPU があれば Ollama が自動で GPU オフロード**（高速・CPU負荷も下がる）。内蔵GPUのみ・専用GPUなしの PC は CPU 推論で動作 |
| モデルの同時常駐 | RAMに連動: **14GB以上は LLM+検索モデルの2常駐**（質問ごとの切替待ちを排除）/ 未満は1つに制限 |
| 並列処理 | 1リクエストずつ処理（KV キャッシュのメモリを節約） |
| コンテキストサイズ | GPU機=8192固定（KVはVRAMに載る）。CPU機は RAM に応じて自動調整（8GB未満=2048 / 8〜16GB=4096 / 16GB以上=8192） |
| CPU優先度 | **CPU推論機のみ** Ollama を「通常以下」で実行（応答中のCPU占有率約82%があっても他アプリを優先。アイドル時の生成速度は低下なし）。NVIDIA GPU 機は生成がGPUへ行くため速度最優先 |
| アプリを閉じたとき | モデルを即アンロードしメモリを解放 |
| モデル選択 | メモリが少ない PC では「軽量（1.5b）」を選ぶと使用量約1GBに抑制 |

目安: 推奨モデル（3b・RAM 8〜16GB）の使用メモリは **約2GB** です。

## 応答速度の自動チューニング

| 設定 | 効果 |
|------|------|
| 2モデル同時常駐（RAM 14GB以上） | LLM（約2GB）と検索モデル（約1.2GB）を常駐させ、質問ごとのモデル切替（実測 +4〜8秒）を排除 |
| 起動時ウォームアップ | PC起動後に自動でモデルをロード。初回質問から再ロード待ちなし |
| 背景生成タスクの無効化 | タイトル/タグ/追質問候補/入力補完の自動生成を停止（回答後にLLMを追加呼び出しして次の質問を遅くするため） |
| 応答長の上限（512トークン） | 長文生成による応答遅延の防止（社内Q&Aは簡潔な回答が十分） |

実測（Ryzen 7 5700U・16GB RAM）: モデル切替が排除され、質問から回答開始までの待ち時間が**約1/2**に短縮されます。

## 低スペック機向けの性能チューニング（インストール時に自動適用）

| 設定 | 効果 |
|------|------|
| KVキャッシュ量子化（q8_0） | コンテキストメモリを約半分に削減（品質への影響はほぼなし） |
| Flash Attention 有効化 | 長文コンテキストの高速化 |
| 常駐モデル数のRAM連動 | メモリ逼迫の防止（上表参照） |
| モデルを60分間キャッシュ | 連続利用時の再読み込み待ちを解消 |
| Ollama を「通常以下」優先度で実行 | AI応答中でも他アプリの操作を優先 |
| Ollama 常駐は Windowsサービスに一本化 | 公式トレイアプリの自動起動を無効化し、ポート競合による起動不良を防止 |

※ AMD系の統合GPU（iGPU）は実測でCPUと同じ速度のため、既定では無効のままにしています（有効化すると初回読み込みが遅くなるだけです）。

## Ollama トレイアプリについて

Ollama 常駐は Windowsサービス（バックグラウンド）に一本化しています。公式の「Ollama」トレイアプリは**意図的に無効化**されます（起動しない・スタートアップに登録されない）。トレイは単なる管理UIで、無効化してもAIの動作には影響しません。元に戻したい場合は `C:\Users\<ユーザー名>\AppData\Local\Programs\Ollama\ollama app.exe.disabled` を `ollama app.exe` にリネームしてください。

## ナレッジ検索（RAG）の仕組みと信頼性

Open WebUI 0.11.0 には、モデルに紐付けたナレッジが RAG 処理へ渡らず検索されない不具合があるため、本ツールは最小パッチ（`scripts/patch_openwebui_rag.py`）で修正しています:

- **ナレッジの自動紐付け**（`scripts/attach_knowledge_to_models.py`）: 登録した社内文書を「社内知恵袋」「経費精算ガイド」「ITヘルプデスク」の3モデルへ自動接続
- **RAG注入パッチ**: 質問に関連する文書の断片を常に自動注入。回答には出典（文書名）が付き「1 Source」バッジで確認可能
- **検索語の固定化**: 検索語をLLMに生成させず、ユーザーの質問文をそのまま検索に使用（3Bモデルの生成する検索語は揺らぎが大きく、関連文書を取りこぼすため）
- **ガードレール**: 参考文書に根拠が無い場合は引用欄を書かず「該当する記載がありません」と回答（履歴に文書名があっても引用禁止）

### パッチ健全性の自己診断

アプリ起動時に `scripts/check_patches.py` がパッチ適用状態を検査し、壊れていたら（例: Open WebUI を手動でバージョンアップした場合）警告を表示します。修復は `scripts/repair_middleware.py`（バックアップから復元→パッチ再適用→サービス再起動）で行えます。

### 「応答なし」問題の対策（ツール無効化）

Open WebUI はモデルに「ツール」（write_note 等およそ34個）を提供します。モデルがツール呼び出しを選ぶとチャットにテキスト回答が残らず「応答なし」に見えることがあるため、本ツールではプリセットモデルですべてのツールを無効化し、qwen3系の思考モードも `think:false` で無効化しています。

## アップグレード（バージョン更新）

新しいバージョンのインストーラを上書きで実行するだけで更新できます:

- **社内文書は引き継がれます**: `{app}\knowledge` に置いた文書に加え、画面のナレッジメニューから追加した文書も自動で退避・再登録されます
- 旧データは `{app}\data.backup-<日付>` に1世代バックアップされます
- チャット履歴は初期化されます（AIモデルの設定・プリセットは自動再構築）
- アップグレード時は自サービスを停止してから前回ポート（既定8080）を再利用します
- 導入後は自動スモークテストで動作を検証します

## 動作検証（スモークテスト）

インストール時に自動実行されるほか、任意のタイミングで手動実行できます:

```
& "C:\Program Files\ShineosQA\venv\Scripts\python.exe" "C:\Program Files\ShineosQA\scripts\smoke_test.py"
```

検証内容: パッチ適用状態 / モデル一覧（プリセットのみ表示）/ ナレッジ紐付け / RAG根拠付き回答（宿泊費→15,000円）/ ガードレール（ナレッジ外の質問→拒否＋架空引用なし）

## 「新機能」ダイアログの非表示

Open WebUI がバージョン更新時に表示する「What's New（新機能）」ダイアログは、ユーザー設定 `showChangelog`（既定で有効）が原因です。本ツールでは:

- アプリ起動時に `showChangelog=false` を自動設定（ラッパーアプリの注入＋サーバー側ユーザー設定の両面）
- 万一表示された場合も自動で閉じる（ja-JP の「OK、始めましょう！」ボタンにも対応）

## ファイル生成（PDF / PPTX / Word）ツールサーバー

チャットから PDF・PowerPoint・Word ファイルを生成できるツールサーバーを同梱しています。

- **軽量サーバー**（`tools/filegen_server.py`）: PDF（reportlab・日本語対応）・PPTX（python-pptx）生成
- **MCPO-File-Generation-Tool**（`tools/mcpo/`・MIT）: PDF・PPTX・**Word（DOCX）**・XLSX・CSV 生成・MCP 対応（日本語フォント対応パッチ適用済み）

インストール時に依存ライブラリの自動インストールと Windowsサービス登録（`ShineosFileGen`・`ShineosMcpoFiles`・`ShineosMcpoMcp`）が行われます。利用方法:

1. Open WebUI の管理画面 → 設定 → ツールサーバーで `filegen` / `mcpo` が登録済みであることを確認
2. ワークスペース → モデル → 社内知恵袋 編集画面の「Tools」でツールを有効化
3. チャットで「PDF（または Word / PowerPoint）を作成して…」と依頼

生成ファイルの保存先: 軽量サーバーは `%USERPROFILE%\shineos-qa-out\`（環境変数 `FILEGEN_OUT` で変更可）、MCPO は `{app}\data\mcpo_output\`。

## インストール時に自動適用される設定

| カテゴリ | 設定内容 |
|---------|---------|
| Embedding | **bge-m3**（日本語・多言語対応の高精度モデル）・直列処理（ENABLE_ASYNC_EMBEDDING=False でキュー停滞防止） |
| 検索 | **ハイブリッド検索**（BM25 キーワード一致 + ベクトル意味一致・BM25重み 0.5）・チャンク 500/オーバーラップ 50・TOP_K 3 |
| モデル | 「社内知恵袋」（汎用）＋「経費精算ガイド」「ITヘルプデスク」の用途別プリセットを自動作成 |
| プロンプト | ガードレール固定（結論先行・根拠の文書名/該当箇所の明記・ナレッジ外は「該当する記載がありません」と回答・CoT による事実整理） |
| ナレッジ | インストール画面で指定したフォルダ（または同梱サンプル）の PDF/Markdown を自動登録（サブフォルダ単位でコレクション分類） |
| その他 | 日本語UI・バージョンアップ通知無効化・閉じたときのモデルアンロード |

### 推奨される追加設定（Open WebUI 管理画面・コマンド不要）

- **コンテキスト圧縮**: 管理画面 → 設定 → チャット → コンテキスト圧縮を有効化（長文チャットのメモリ節約・応答安定化）
- **RAG 関連の詳細調整**: 管理画面 → 設定 → ドキュメント（検索結果の表示件数・関連性しきい値など）

## UI設定（言語・通知）

- **言語**: インストール時に日本語（ja-JP）を自動設定。手動切り替えは Open WebUI の「設定 → 一般 → 言語」
- **バージョンアップ通知・「What's New」通知**: 無効化（`ENABLE_VERSION_UPDATE_CHECK=False`）
- **アプリを閉じたとき**: Open WebUI サービス停止 + Ollama のロード済みモデルを自動アンロード（メモリ解放）
- **デスクトップショートカット**: インストール時に自動作成（「社内知恵袋」）

## Web検索（オプション）と検索エンジンの切替

- Web検索は既定 OFF（チャット入力欄のWeb検索ボタンで ON/OFF）。ON にすると質問内容が外部の検索サービス（DuckDuckGo・APIキー不要）へ送信されるため、社内情報の質問時は OFF のままにしてください
- 社内ネットワーク向けの SearXNG への切替手順は[構築ドキュメント §3.2](build.md#32-検索エンジンの切替searxng)を参照

## アンインストール時のデータ扱い

- アンインストール時に「ナレッジ（社内文書・検索データ）を残すか？」を確認（アップグレード目的なら「はい」で保持）
- Ollama 本体・AIモデル（約2〜5GB）も削除するかを個別に確認
- 完全削除を選んだ場合、SYSTEMプロファイル側のモデルも含めて掃除します
