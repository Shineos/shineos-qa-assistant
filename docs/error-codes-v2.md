# v2 エラーコード・終了コード・サイレントインストール設計（Microsoft Store対応込み）

- 日付: 2026-09-13（設計）
- 対象: v2アーキテクチャ（[architecture-v2.md](architecture-v2.md)）のインストーラ・バックエンド・スーパーバイザ
- 継承: v1の [exit-codes.md](exit-codes.md) の方針（Inno標準コード＋独自コードは一意のみ・Store申請の「EXEリターンコード値」根拠資料）を引き継ぎ、v2の新失敗モード（エンジン/モデル検証・サービス・移行）とランタイムAPIエラーを追加

---

## 1. 設計原則

1. **シナリオ別に一意な終了コード**: Microsoft Store のインストール分析および無人展開（Intune/SCCM/GPO）が失敗を分類できる。1つのコードが複数シナリオを兼ねない
2. **成功=0・再起動要求なし**: すべての経路で再起動を要求しない（Inno標準8は返さない設計）
3. **終了コード ↔ ログの対応**: 非ゼロ終了時、必ず `{app}\logs\install-<date>.log` に同じコードと相関ID（例: `INST-20260913-4F2A`）を記録。ユーザーはコード1つでサポートに連絡できる
4. **段階的劣化（degrade）を明示**: リランカ未導入・ウォームアップ失敗など「警告のみで続行」する項目と「失敗として中断」する項目を区別し、警告は成功(0)＋警告ログで返す
5. **サイレントファースト**: 対話UIなしで全機能が使える（§6）。ストア・企業展開双方の要件

## 2. インストーラ（ShineosQA-Setup-v2.exe）終了コード

0〜8 は Inno Setup 標準（v1と同一）。11以上が本製品の独自コード（カスタム終了コード機構で返却。**v1の11〜14の意味は変更しない**）:

| コード | シナリオ | v2での発生条件 | 中断/継続 |
|---|---|---|---|
| **0** | 成功 | 全ステップ完了（警告のみの項目を含む） | — |
| 1 / 2 / 4 / 5 | Inno標準（初期化失敗／開始前キャンセル／処理中エラー／処理中キャンセル） | Inno機構による | — |
| **11** | 同一バージョン完了済み | `/VERYSILENT` で完了済み環境に再実行 | 即時終了 |
| **12** | ディスク空き容量不足 | 必要容量（モデル選択後の合計＋1GB）未満 | 中断 |
| **13** | ダウンロード失敗（ネットワーク） | llama.cppエンジンzip／GGUF／（CUDA版）のDLが再試行後も失敗。ミラーフallbackも失敗 | 中断 |
| **14** | セキュリティポリシーによる拒否 | AppLocker/SmartScreen等（参考値。プロセス起動自体がブロックされるため通常観測されない） | — |
| **15** | エンジン整合性検証失敗 | llama.cpp zip のSHA256がカタログ不整合 | 中断 |
| **16** | モデル整合性検証失敗 | GGUF のSHA256がカタログ不整合（モデルIDをログに記録） | 中断 |
| **20** | サービス登録失敗 | `ShineosQA`（バックエンド）サービス作成/設定失敗 | 中断 |
| **21** | バックエンド起動失敗 | サービス開始後、ヘルスチェック（`/health`）が120秒以内にOKにならない | 中断（ログにsupervisorログを添付） |
| **22** | ポート競合 | 既定ポート（8080）占用で代替ポートも確保不能 | 中断 |
| **30** | v1からの移行失敗 | v1検出環境でのナレッジ再取り込み（再チャンク+再埋め込み）失敗 | 中断（v1環境は保持） |
| **31** | 旧構成削除失敗 | 移行時のOllama/OWUI削除ステップ失敗（ユーザー承認済みの削除） | **警告で継続(0)**…ただし旧サービス停止は必須。停止不能時は31で中断 |
| **40** | スモークテスト失敗（RAG） | インストール直後の実Q&A検証（正答/ガードレール）不合格 | 中断 |
| **41** | スモークテスト失敗（埋め込み） | 埋め込み応答検証不合格・タイムアウト | 中断 |
| **90** | 内部エラー | 想定外の例外（例外種別と相関IDをログに記録） | 中断 |

**警告で継続する項目（成功=0・警告ログ＋UI通知のみ）**: ウォームアップタスク登録失敗／リランカDL失敗（16GB未満では元々スキップ）／Vulkan版DL失敗（CPU版へフォールバック）／起動時ウォームアップのタイムアウト

## 3. 内部コンポーネントの終了コード（install-*.log 切り分け用）

インストーラ内部で起動する v2 コンポーネント（セットアップ EXE 自身の終了コードではない。`STEP FAILED: <名前> (exit <コード>)` として記録）:

| コンポーネント | 終了コード |
|---|---|
| `preflight2.ps1`（環境判定: RAM階級/GPU/ポート） | 0=OK / 12=ディスク不足 / 22=ポート競合 |
| `download-engine.ps1` | 0=成功 / 13=DL失敗 / 15=SHA不一致 / 90=内部エラー |
| `download-model.ps1`（chat/embed/rerank共通・対象IDをログ） | 0=成功 / 13=DL失敗 / 16=SHA不一致 / 90=内部エラー |
| `install-service.ps1` | 0=成功 / 20=サービス登録失敗 / 21=ヘルスチェック失敗 / 22=ポート |
| `migrate-v1.ps1`（ナレッジ再取り込み＋Ollama削除） | 0=成功 / 30=再取り込み失敗 / 31=旧構成削除失敗 / 90=内部エラー |
| `smoke-test2.ps1` | 0=全項目合格 / 40=RAG不合格 / 41=埋め込み不合格 |
| `ShineosQA.Backend --selftest`（升格前の自己診断: ポート/DB/設定/エンジン起動） | 0=OK / 21=起動不可 / 22=ポート / 23=DB初期化失敗 |

## 4. バックエンド HTTP API のエラーモデル（ランタイム）

### 4.1 エンベロープ

```json
{
  "error": {
    "code": "SHINE_E_ENGINE_TIMEOUT",
    "message": "AIエンジンからの応答がタイムアウトしました。しばらく待ってから再試行してください。",
    "correlation_id": "RUN-20260913-9X41",
    "details": { "engine": "llm", "timeout_ms": 120000, "retryable": true }
  }
}
```

- `message` は常に日本語・エンドユーザー向き。技術詳細は `details` とログ（相関IDで突き合わせ）
- `retryable: true` の場合UIは「再試行」ボタンを表示

### 4.2 エラーコード一覧

| code | HTTP | 意味 | UI挙動 |
|---|---|---|---|
| `SHINE_E_BAD_REQUEST` | 400 | リクエスト不正 | 入力修正を促す |
| `SHINE_E_ENGINE_DOWN` | 503 | LLMエンジン子プロセス停止（再起動中） | 自動再試行（最大3回・指数バックオフ） |
| `SHINE_E_ENGINE_TIMEOUT` | 504 | LLM応答タイムアウト | 再試行ボタン |
| `SHINE_E_EMBED_DOWN` | 503 | 埋め込みエンジン停止 | ナレッジ登録を一時不可表示。チャットは既存ベクトルで継続可 |
| `SHINE_E_RERANK_UNAVAILABLE` | — | リランカ未導入/停止 | **エラーにせず自動でリランク無しにdegrade**（応答に `"reranked": false` を付与） |
| `SHINE_E_MODEL_NOT_FOUND` | 404 | 選択モデルのGGUF不在 | モデル管理画面へ誘導 |
| `SHINE_E_MODEL_HASH` | 500 | モデルファイル破損検出（起動時SHA検証） | 再ダウンロード誘導 |
| `SHINE_E_DOC_PARSE_FAILED` | 422 | PDF/DOCX解析失敗（ファイル単位） | 該当ファイルをスキップして継続（結果に反映） |
| `SHINE_E_DOC_TOO_LARGE` | 422 | ファイルサイズ超過（上限100MB） | ファイル分割を促す |
| `SHINE_E_KB_BUSY` | 409 | ナレッジ取り込み中の競合 | 进捗UI表示・完了後再試行 |
| `SHINE_E_DISK_FULL` | 507 | ディスク残量不足（モデルDL/ログ） | 空き容量確保を促す |
| `SHINE_E_OOM` | 503 | エンジンがOOMで停止（supervisorが検出） | RAM階級を1つ下げた設定で自動再起動（ctx縮小/軽量モデル）。継続不能時は案内 |
| `SHINE_E_RATE_LIMITED` | 429 | 同時リクエスト超過（既定1） | 順番待ち表示 |
| `SHINE_E_MODEL_DOWNLOAD_FAILED` | 502 | 初回起動時のモデルGGUF取得失敗（再試行・ミラーfallback後。終了コード体系上はDL系13と同系列のランタイム版） | 再試行ボタン・ネットワーク確認 |
| `SHINE_E_MODEL_VERIFY_FAILED` | 500 | DLモデルのSHA256不一致（§2の16相当） | 再ダウンロード／破損ファイル削除を自動试行 |
| `SHINE_E_INTERNAL` | 500 | 想定外例外 | 相関IDとともにエラー画面 |

### 4.3 NO-HIT はエラーではない

ナレッジ外質問は `200` ＋ 本文「該当する記載がありません」（リランク全候補負値→**推論前ガード**で固定文即答。回帰テストで実測: 10〜17s→約4.5s）。

## 5. サービス（スーパーバイザ）の終了コードと回復

- Windowsサービス `ShineosQA`（バックエンド）の**プロセス終了コード**:
  - `0`: 正常停止（アンインストール/シャットダウン）
  - `10`: 設定ファイル破損で起動不能（`config.json` 再生成で回復試行→失敗時）
  - `11`: ポートバインド失敗
  - `12`: `knowledge.db` 破損（SQLite整合性チェック失敗。バックアップからの自動復元を試行）
  - `90`: 想定外例外
- **SCM 回復ポリシー**: 失敗→0秒で再起動／3回失敗→60秒待機→再起動／10回失敗で停止し Windows イベントログ（Source: `ShineosQA`, EventID 下表）に記録
- 子プロセス（llama-server）異常終了は**サービスを落とさない**: supervisorが検出し指数バックオフで再起動（LLM: 最大5回／embed: 最大5回／rerank: 1回失敗で恒久的にdegrade）。OOM検出時はフラグ引数を縮小して再起動（§4.2 `SHINE_E_OOM`）

| イベントログID | 種別 | 内容 |
|---|---|---|
| 1001 | Information | サービス開始（バージョン・モデルID・モード） |
| 2001 | Error | 子プロセス異常終了（engine種別・exit code・再起動回数） |
| 2002 | Error | OOM検出と縮小再起動 |
| 3001 | Error | サービス自己終了（上記終了コード10/11/12/90と相関ID） |

## 6. サイレントインストール・アンインストール仕様

### 6.1 インストール（無人）

```
ShineosQA-Setup-2.0.0.exe /VERYSILENT /SUPPRESSMSGBOXES /NORESTART [/LOG="<path>"]
  [/MODEL=standard|quality|light]      … 既定: RAM階級で自動選択
  [/KNOWLEDGE="<dir>"]                 … 初回取り込みフォルダ（省略時: サンプルのみ）
  [/PORT=<1-65535>]                    … 既定8080。競合時は自動回避（失敗=22）
  [/SKIPVERIFY=1]                      … GGUF SHA検証スキップ（検証環境用。通常非推奨）
  [/NORERANK=1]                        … リランカDLをスキップ
  [/UNATTENDED=1]                      … v1検出時の「Ollama削除」確認を自動承認
```

- `--retry` 付きDL再試行（3回・指数バックオフ）＋ミラーfallback後の失敗が13
- 進捗は `{app}\install-progress.ini`（v1のINIポーリング方式を踏襲。RMM/SCCMから観測可能）
- **応答ファイル対応**（`/SAVEINF` `/LOADINF`）: モデル・ポート・ナレッジ等の選択をファイル化して一括展開
- 完了判定: 終了コード0 ＋ `{app}\logs\install-*.log` の `===== INSTALL COMPLETED =====`

### 6.2 アンインストール（無人）

```
unins000.exe /VERYSILENT /SUPPRESSMSGBOXES /NORESTART [/PURGE=all|models|knowledge]
```

- 既定: `{app}` 配下とサービス・ウォームアップタスクのみ削除（**他アプリ・ユーザーのOllama等には触らない**）
- `/PURGE=models`: GGUF削除（約3GB解放）／`all`: knowledge.db含む全データ
- v1とは異なり Ollama アンインストーラ呼び出し・env/IFEO掃除が不要（自己完結型のため）。失敗しても孤立ファイルは残すが終了コードは0（警告ログ）——Storeの「クリーンアンインストール」要件と整合

### 6.3 アップグレード（v1→v2）

1. v1検出（サービス/`C:\Program Files\ShineosQA`）→ 対話時は「旧構成（Ollama/Open WebUI）を削除する」確認。`/UNATTENDED=1`で自動承認（既定動作: 削除）
2. ナレッジ原典（`{app}\knowledge`）を新パイプラインで再取り込み → 失敗=30（v1環境保持のまま中断）
3. Ollama/OWUI削除（サービス停止→アンインストーラ→`%USERPROFILE%\.ollama` 等）→ 停止不能=31
4. チャット履歴はオプション移行（webui.db→knowledge.db）

## 7. Microsoft Store 申請対応

**方針: v1と同じく Inno Setup 製 EXE を Store に提出**（Store の MSI/EXE インストーラ提出対応を利用。MSIX化は§7.2で検討）。

|---|---|---|

### 7.2 MSIX化する場合の検討事項（将来オプション）

- v2は**自己ディレクトリ完結・グローバルenv不使用・IFEO不使用**のためMSIX適合性が高い（v1はOllamaが外部ソフトでMSIX化困難だった）
- WindowsサービスはMSIX+`runFullTrust`で登録可能。ただし `%PROGRAMFILES%` 直下前提の既存Inno資産との二重管理に注意
- 段階判断: Store審査でEXE提出が安定するならMSIX不要。要否はリリース運用で決定

## 8. ログと相関ID

- **インストール**: `{app}\logs\install-YYYYMMDD.log`（相関ID `INST-…`。終了コードと同名の行で終端）
- **ランタイム**: `{app}\logs\backend-YYYYMMDD.log`（構造化行: `ts level code corr_id engine ...`。`RUN-…`相関IDはAPIエンベロープと一致）
- **エンジン**: supervisorが子プロセスのstderrを `{app}\logs\engine-<llm|embed|rank>.log` へリレー（起動フラグ付きヘッダ）
- ローテーション: 日次・1ファイル上限10MB・14世代。`SHINE_E_DISK_FULL`時は一時的に圧縮
